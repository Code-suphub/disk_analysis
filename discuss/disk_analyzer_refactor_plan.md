# 磁盘分析工具重构方案：从全量扫描转向增量统计

## 1. 背景与现状
当前实现采用全量递归扫描方案（`os.walk` + `ThreadPoolExecutor`），在处理大型硬盘或深层文件系统时存在以下问题：
- **内存占用高**：在内存中构建完整的树状结构，容易导致 OOM。
- **响应速度慢**：用户必须等待全量扫描完成后才能查看结果。
- **系统资源消耗大**：即使只想查看顶层文件夹，也会遍历所有子目录。

## 2. 目标方案
参考用户建议，将全量扫描改为**增量统计 + 系统命令辅助**方案。

### 2.1 高级统计 (Disk Overview)
- 使用 `shutil.disk_usage()` 或解析 `df -h` 命令输出，提供磁盘分区的整体容量及使用百分比提示。

### 2.2 增量扫描 (Incremental Scanning)
- **按需加载**：初始仅扫描用户选择的根目录的二级目录（或当前展开的层级）。
- **节点大小统计**：
    - 对于单个节点，使用 `du -sh` (macOS/Linux) 或 Python 递归计算该直接子项的大小。
    - 这样用户可以在不扫描整盘的情况下，快速定位哪个一级目录占用了最多空间。
- **后端接口变更**：
    - `get_disk_usage()`: 返回系统磁盘列表及使用情况。
    - `list_directory_details(path)`: 返回该路径下的直接子文件和子目录，并包含每个子项的总大小（Size）。

## 3. 技术实现细节

### 3.1 后端 (Python/scanner.py)
- 废弃 `DiskScanner.scan_directory` 递归构建整树的逻辑。
- 新增 `get_directory_items(path)` 方法：
    - 只读取 `os.listdir(path)`。
    - 对每个子项（特别是子目录），单独调用大小计算逻辑（优化可以使用缓存或底层系统调用）。
- 计算文件夹大小可以考虑 `du -d 1` 这种系统原生命令以提升性能。

### 3.2 前端 (Electron/Renderer)
- UI 修改为树形控件（Tree View）或层级列表。
- 只有当用户点击展开节点时，才触发对该路径的后端请求。
- 增加“磁盘概览”面板。

### 3.3 交互流程
1. 用户启动应用，后端返回磁盘基础信息。
2. 用户选择一个路径，后端返回该路径下的文件/文件夹清单及各自的大小。
3. 用户点击某个文件夹，前端请求后端获取该子文件夹的详细内容。

## 4. 优势
- **极低的内存需求**：只需存储当前可视层级的数据。
- **极速响应**：无需等待数分钟的扫描过程。
- **可扩展性**：支持对海量小文件的快速分析。

## 5. 跨系统兼容性方案 (Cross-Platform Compatibility)
为了确保在 Windows、macOS 和 Linux 上都能稳定运行并保持高性能，我们将采取分层策略：

### 5.1 基础层 (通用 Python 实现)
- 使用 `shutil.disk_usage(path)` 获取分区的总大小、已用和可用空间。该函数在所有主流 OS 上表现一致。
- 使用 `os.scandir(path)` 代替 `os.listdir(path)`。`scandir` 在获取文件属性时性能更高，且在 Windows 上能显著减少系统调用。

### 5.2 优化层 (平台特定命令)
当基础层性能不足时，后端将根据 `platform.system()` 调用最优工具：
- **macOS / Linux**: 
  - 使用 `du -d 1 -k <path>` 快速获取直接子目录的大小。
  - 使用 `df -h` 获取挂载点详细信息。
- **Windows**:
  - 使用 `wmic logicaldisk get caption,size,freespace` 或 PowerShell 命令获取磁盘信息。
  - 文件夹大小计算：由于 Windows 没有原生的 `du` 命令，我们将使用 Python 的 `os.scandir` 结合多线程进行优化（Windows 的文件系统元数据读取较慢，增量加载是关键）。

### 5.3 路径兼容性
- 统一使用 `pathlib` 处理路径，自动处理 `\` (Windows) 与 `/` (Unix) 的差异。

## 6. 待讨论点
- 在计算某个文件夹大小时，是否需要后台异步并发计算所有同级目录的大小？
- 对于 macOS，使用原生 `du` 命令是否会比 Python `os.walk` 更快？（通常是的，因为其内部实现更贴近硬件）。
